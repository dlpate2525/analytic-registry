# Analytic Registry V1.1 prototype

Local working version `1.1.0-prototype.3-local`, 9 October 2026. The last published tag remains `v1.1.0-prototype.2`. The frozen [V1 baseline](v1-prototype-baseline.md) remains available.

V1.1 focuses on the data foundation and operating process. It adds a smaller query-first extract contract, explicit platform mappings, a consolidated identity design, and white surfaces with purple and coral accents.

## Working layout update

The working V1.1 prototype now uses a [fixed 1366 × 768 tablet canvas](v1.1-canvas-layout.md). It scales proportionally and scrolls long pages internally. This update follows the frozen query revision 2 baseline; it does not change that Git tag or the extract contract.

## Local workflow and evidence update

Approved owner and Champion assignments now take effect independently of technical implementation. Register Existing completes business registration after required information, approvals, and the effective date. Required technical work remains one linked task.

The SQL diagnostics and workbook distinguish structural rejection from accepted unresolved references. Routine acceptance belongs to the registry operator. Platform Manager owns unresolved cases. Browser indicators distinguish usable inventory from evidence sufficient for a control comparison.

[Documented platform samples](resources/platform-data-collection/v1.1-extract/samples/README.md) cover initial, replay, and changed-refresh deliveries for Alteryx, Tableau, and Fabric. They validate reference logic with synthetic records; they do not establish installed-source execution.

## Local request module update

The local [workspace request module](v1.1-request-module.md) now owns request actions and status. Screens and scenario tests share its interface. The five-step form, required approvals, effective dates, and separate technical work remain.

## Published query revision 2

Alteryx now runs as T-SQL over exported Gallery and Service tables. Tableau has an ordinary PostgreSQL query-editor batch. Fabric has a landed-inventory SQL query and DAX discovery. The Excel input headers and identity namespaces are unchanged. The Power BI reference tab distinguishes the narrower Fabric route from the richer existing scan-export route.

The frozen `v1.1.0-prototype.1` tag remains unchanged.

## What changed

- [Excel template](resources/platform-data-collection/v1.1-extract/analytic-registry-v1.1-extract.xlsx): nine data tables with 60 columns; run context and coverage add 12 columns across two tables.
- [Dictionary](resources/platform-data-collection/v1.1-extract/column-dictionary.csv): 216 explicit platform/column mappings with source, value, and NULL rules.
- [Source queries](resources/platform-data-collection/v1.1-extract/source-query-design.md): Tableau PostgreSQL, Alteryx SQL Server over exported Gallery/Service tables, and Fabric SQL over landed inventory. No application API calls are introduced.
- [Model](v1.1-model-simplification.md): 12 proposed foundation entities; one Person with multiple SourceIdentity accounts. The full 45-table consolidation remains an undeployed proposal.
- [Monthly reconciliation](resources/platform-data-collection/v1.1-extract/monthly-reconciliation.md): native keys, replay, late arrivals, coverage, identity matching, and protected history.
- The Data foundation page filters input rules by platform and dataset. It also shows application entities and executable synthetic refresh examples.
- The visual design uses white surfaces with purple actions and coral accents. Five main sections and existing workflows remain.

## Product rules retained

Business Owner and Workspace Owner are one field. Champions remain with workspace accountability. PII, EUCT, and highest DMP tier remain declarations; Tier 1 is highest. Approved PRL is manual, never a calculated score. The _DS group creates and maintains workspace connections.

Custom setup and annual attestation require the agreed owner role. Evidence closure requires Platform Manager, Platform Team, or Platform Owner. Self-approval remains allowed for an eligible role holder. Unresolved identity and relationship cases go to Platform Manager.

Monthly platform refresh never overwrites business declarations or historical approvals. Six months of superseded history does not remove durable identity mappings or active evidence.

## Implemented versus proposed

Implemented locally: React foundation screens, dictionary and workbook artifacts, query templates, staging/validation SQL files, and reference comparison logic. Existing browser workflows still use mock data.

Proposed or unverified: live source extraction, actual Alteryx export mapping, SQL query execution, database deployment, scheduled acceptance and retention, IAM authorization, and an import-tested Power Apps app. No raw platform data is published.

The previously prepared Canvas tooling has not produced a completed `.msapp`. Canvas conversion should use this reviewed V1.1 foundation. This release must not be described as a deployed Power App.
