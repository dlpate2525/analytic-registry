# Evidence behind the sample fixtures

Reviewed: 9 October 2026. These fixtures contain synthetic records shaped from vendor documentation and the V1.1 query contract.

No vendor supplied this sample dataset. All identifiers, names, emails, dates, and counts are invented test values.

## Alteryx

The selected Gallery reference documents these source fields:

| Entity | Documented fields used by the examples |
|---|---|
| `collections` | `_id` is ObjectId; `CollectionId`, `Name`, and `OwnerId` are strings. `Apps` and `Users` are arrays. |
| `appInfos` | `_id` is ObjectId. `CreatedBy` is the original author. `ServiceId` references the Service application. |
| Published revision | `RevisionId` is a string. `IsPublishedRevision` and `IsPrimaryApp` are booleans. `MetaInfo.Name` is a string. |
| `users` | The query keeps the source user ID, name, email, and source activity flag. |

These are MongoDB fields, even when their exports reside in SQL Server. The sample decodes ObjectIds into text. It retains nested arrays. `CreatedBy` does not establish current workflow ownership. [Alteryx Gallery schema](https://help.alteryx.com/20251/en/server/configure/database-management/mongodb-management/mongodb-schema-reference/alteryxgallery-mongodb-schema.html)

The Service reference documents `AS_Applications._id` as ObjectId and `UserName` and `ModuleName` as strings. The query uses these for a cross-reference. It does not treat the Service username as current ownership. [Alteryx Service schema](https://help.alteryx.com/20251/en/server/configure/database-management/mongodb-management/mongodb-schema-reference/alteryxservice-mongodb-schema.html)

The supplied field pages describe 2025.1. The version crosswalk lists Gallery schema 79 and Service schema 8 for 2025.2. This mismatch remains explicit. The sample does not certify the installed 2025.2 export. [Alteryx version crosswalk](https://help.alteryx.com/current/en/server/configure/database-management/mongodb-management/mongodb-schema-reference.html)

The official field pages were read successfully through HTTPS after the browser search tool returned access errors. Native SQL persistence documentation was not substituted.

## Tableau

The 2026.2 repository dictionary documents separate project, workbook, datasource, connection, site, and user records. The samples preserve LUIDs for registry identity. Repository integer IDs remain local joins.

`projects_contents` supplies project membership. Connection owner references supply asset connections. The source user joins through `system_user_id` to the system-user email. A site role does not establish directory account activity.

The example uses explicit `SAMPLE_*` content and owner tokens. These are fixture-only parameters. They do not claim to be installed Tableau tokens. The dictionary cautions that repository structures can change. [Tableau 2026.2 repository dictionary](https://tableau.github.io/tableau-data-dictionary/2026.2/data_dictionary.htm)

## Fabric

Microsoft documents item IDs, workspace IDs, names, and item types in its inventory reporting. The sample uses those meanings. It maps a semantic model to the existing registry type `Dataset`. An activity status is not an item lifecycle or directory status. [Feature usage and adoption](https://learn.microsoft.com/en-us/fabric/admin/feature-usage-adoption)

Govern supports custom reports from its autogenerated semantic model. Its estate data refreshes daily. The page does not define a fixed SQL table schema for the model. The sample therefore uses the existing organization-owned `registry_source.FabricInventory` adapter. [Govern documentation](https://learn.microsoft.com/en-us/fabric/governance/onelake-catalog-govern)

The SQL analytics endpoint exposes lakehouse Delta tables. Creating an endpoint does not create tenant-wide administration tables. [SQL analytics endpoint](https://learn.microsoft.com/en-us/fabric/data-engineering/lakehouse-sql-analytics-endpoint)

## Directory evidence

Microsoft defines a directory user's stable `id`, `mail`, and `accountEnabled` properties. The separate synthetic evidence uses these meanings. Source platform activity never overrides `accountEnabled`. No Office 365 lookup or Graph request runs during sample validation. [Microsoft user resource](https://learn.microsoft.com/en-us/graph/api/resources/user?view=graph-rest-1.0)

## What the evidence proves

The documentation supports the field meanings. Local tests check contract shapes and the app's reference comparison and email-resolution functions.

The evidence does not prove installed table names, SQL execution, complete source coverage, transactional imports, or persisted case deduplication. These require separate implementation and environment checks.
