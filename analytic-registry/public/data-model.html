Design decisions

Multiple tables, purpose-built views

Keep normalized base tables at their natural grain. Give each Power Apps screen a read view with a stable row key. A flat gallery is a presentation choice, not a single-table storage model.

Platform is explicit, identity is scoped

PlatformID lives on PlatformInstance and DetectionCoverage. Every technical object resolves to PlatformID through its instance. Include PlatformID and PlatformName in workspace, asset, connection, review, and finding views. Do not duplicate editable platform text on every child record.

Names can change; identity cannot

RegistryObject uses an internal UUID. Native identity is unique within platform instance, native scope, and object type. A draft can have no native ID. Discovering a provisioned object must bind to the existing request identity or enter a reconciliation queue; never join by name alone.

Membership is not ownership

WorkspaceAsset records declared associations. ObservedWorkspaceAsset records extracted membership. An asset can have multiple collection memberships and still have a single accountable workspace under the confirmed business rule. An orphan is a resolvable asset with a missing required association, not an asset that disappears from the database.

Four sources remain separate

Business versions capture purpose and accountability. Requested versions capture desired setup. Implemented versions capture what an administrator records as implemented. Observed snapshots capture what extracts show. RuleEvaluation compares pinned versions and evidence.

Absence requires complete evidence

ExtractDataset records completeness by dataset and scope. Missing membership in a partial or failed extract cannot prove removal. Select a complete snapshot for each dataset; do not mix arbitrary latest rows from unrelated runs.

One finding, many detections

Finding owns the stable lifecycle. RuleEvaluation and FindingEvaluation retain each detection. Pending implementation is a comparison state. Unsupported detection and missing evidence remain unresolved. Neither automatically becomes a failed control.

Server commands enforce multi-row rules

Draft edits may be incomplete. Submission checks eligible owner, 1–10 unique Champions, group prerequisites, Custom reasons, and field limits in one transaction. SQL constraints enforce keys; the command enforces cross-row counts and effective dates.

Column dictionary

PK = primary key; FK = foreign key; uuid = uniqueidentifier. NULL is explicit. Unmarked FK columns are required. Every table also has CreatedAt datetime2 NOT NULL. Mutable app records add ModifiedAt, ModifiedByPersonID, and RowVersion.
