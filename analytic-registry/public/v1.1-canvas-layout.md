# V1.1 tablet canvas

The prototype uses a fixed **1366 × 768** design area for future Power Apps testing.
This is an accepted V1.1 layout requirement. The browser prototype remains a React application.

## Display contract

| Setting | Value | Meaning |
|---|---|---|
| Design width | 1366 pixels | Horizontal design coordinates. |
| Design height | 768 pixels | Vertical design coordinates. |
| Layout | Tablet, landscape, 16:9 Default | Shared review size for every screen. |
| Scale to fit | On | Fit the complete canvas inside the available player area. |
| Lock aspect ratio | On | Scale both dimensions equally; leave margins when needed. |
| Lock orientation | On | Keep the landscape arrangement when the device rotates. |

Microsoft documents [1366 × 768 for the landscape default](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/create-responsive-layout).
Its [display settings guide](https://learn.microsoft.com/en-us/power-apps/maker/canvas-apps/set-aspect-ratio-portrait-landscape) describes scaling and aspect-ratio behavior.
Set these options through Power Apps **Settings > Display** when creating the actual app.
The design dimensions are often referenced as `App.DesignWidth` and `App.DesignHeight` in existing Canvas material.

## Browser behavior

The browser scales the complete canvas proportionally. Window resizing does not rearrange fields or collapse navigation automatically.
The user can still collapse navigation with its existing button.

Navigation, the header, and the footer remain inside the canvas. Long pages scroll in the central content area.
Wide data tables keep their own horizontal scrolling. Workflow actions retain their existing sticky positioning.
Dialogs and notifications stay within the canvas. Dialog content scrolls when needed.

White surfaces, purple actions, coral accents, five main sections, and existing process steps remain.
Small windows show a smaller landscape canvas. A separate phone layout is outside this fixed-size prototype requirement.

## Review procedure

1. Open the browser prototype at a 1366 × 768 content viewport.
2. Check each main section and the administration pages.
3. Open each guided form and reach its action buttons.
4. Scroll long records and wide tables.
5. Open the review guide and check its close button.
6. Resize the window and check proportional scaling.

Browser dimensions exclude browser tabs, address bars, and operating-system borders.
Test at the actual player dimensions when a Power Apps environment becomes available.

## Conversion boundary

The offline Canvas seed now declares the same six display settings explicitly.
It contains no completed application screens and is not an import-tested `.msapp`.
The seed's earlier V1 bindings still require migration to the V1.1 data contract.
