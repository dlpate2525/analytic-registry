# Analytic Registry V1.2 prototype release

Application: **1.2.0-prototype.1**. Intended Git tag: **v1.2.0-prototype.1**. Preparation date: **21 October 2026**.

This prototype combines observed platform inventory with separately managed business accountability. Platform identity, names, and counts remain source observations. Source refreshes must preserve approved business metadata.

The workbook revision is **1.2**. Its input schema remains **1.1**, with 11 input tables and 72 column positions across those tables. The workbook contains 16 sheets, including guidance and three platform mapping tabs.

## Current scope

- Five main business sections cover Dashboard, Workspaces, Assets, Requests, and My work. Administration holds platform imports and supporting reference pages.
- Each workspace has one Workspace Owner. Champions have equal authority. Current approved assignments determine the applicable business actions.
- Asset evaluations record business context and calculate PRL. PRL 1 or a qualifying governance answer makes the asset High risk.
- Assets do not receive Annual Attestations. Workspace Annual Attestation remains a separate workflow.
- Platform imports describe Receive, Validate, Match, Compare, and Accept. Live acceptance is not connected in this React prototype.
- Detection Coverage explains supported evidence. Risk Buckets group possible findings. These descriptions do not prove that live detection runs.

Read the [product and workflow guide](v1.2-guide.md), [requirements](v1.2-requirements.md), and [risk and coverage guide](v1.2-risk-and-coverage.md) for the exact behavior and boundaries.

## Platform delivery

Use the [V1.2 Excel workbook](../../platform-data-collection/v1.2-workbook/analytic-registry-v1.2-extract.xlsx) and [platform handoff](../../platform-data-collection/v1.2-workbook/README.md).

Tableau uses PostgreSQL repository queries. Alteryx uses SQL Server queries over exported Gallery and Service data through explicit adapters. Fabric uses queries over landed inventory, with documented alternatives for existing exports.

Preserve native identifiers for monthly reconciliation. Match people by email within the configured directory tenant. Route unresolved identities to Platform Manager. An unresolved account does not establish that the person is inactive.

Partial extracts cannot establish deletion, orphan status, or retirement. Platform membership does not replace the confirmed accountable workspace.

The release preparation command builds artifacts. It does not create a GitHub release or establish successful publication.

## Limits

This is a React prototype with fictional records and browser storage. Browser role switching does not provide production authorization.

Installed Tableau, Alteryx, Fabric, and SQL Server execution remains unverified. Query fixtures and mappings are preparation evidence, not proof of compatibility with a particular installation.

Live ingestion, directory resolution, SQL deployment, and Power Apps import remain integration work. The release is not an importable production Canvas app.

Annual policy details, retirement behavior, freshness thresholds, usage thresholds, and shared-case closure rules remain unresolved where the requirements say so. This release does not invent those rules.
