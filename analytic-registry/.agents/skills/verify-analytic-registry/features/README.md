# Analytic Registry verification map

Each feature starts with normal seed data in isolated browser storage. Launch and evidence rules are in [SKILL.md](../SKILL.md).

| Runner argument | Feature recipe | Coverage |
| --- | --- | --- |
| `workspaces` | [Dashboard and workspaces](workspaces.md) | Counts, profile scope, filters, legacy links, inventory context, canvas scaling |
| `assets` | [Assets](assets.md) | Completed evaluation, current version, accountability confirmation and correction |
| `requests` | [Requests](requests.md) | Business-only submit and Champion approval, technical groups, stale-tab protection |
| `work` | [My work and Annual Attestation](work.md) | Queue mapping and filters, case evidence requirements, frozen annual context |
| `administration` | [Administration and imports](administration.md) | Walkthrough boundary, reference pages, browser export, storage recovery |

These are bounded journeys, not every branch of the application. Run domain checks for detailed PRL bands, identity matching, request eligibility, migration, and import comparison. Retrospective execution chronology, late-approval precedence, future annual policy, retirement operations, freshness thresholds, and shared-case policy remain unsettled.

Read the matching recipe, run its argument, then inspect `run.json` and that feature's `result.json`. A failed prerequisite is a failure to investigate, not a reason to delete an assertion. A route inspected directly does not prove every menu or record link that reaches it.
